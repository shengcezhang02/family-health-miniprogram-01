# 家庭健康小程序开发 Milestones

状态：已确认；M0、M1 已完成；M2 实现和单账号验证已完成，等待第二账号联调

依据：Obsidian 中的《家庭健康小程序：精简版项目文档》

开发方式：原生微信小程序 + CloudBase + TDD

## 1. 目的

本计划把第一轮实现拆成 10 个可以独立编译、自动测试和交给人类验收的纵向 milestone。

每个 milestone 都必须提供一条从页面到云端或领域行为的完整路径。不会先把所有页面画完、再统一写云函数，也不会先写一大批测试后再实现。

## 2. 当前项目基线

- 微信开发者工具已经登录并打开本项目；
- 当前运行页面是 QuickStart 的 `pages/index/index`；
- 项目包含 `miniprogram/` 和 `cloudfunctions/`；
- 当前只有 QuickStart 示例页和 `quickstartFunctions` 示例云函数；
- `miniprogram/app.js` 中的云环境 ID 仍为空；
- 项目尚未初始化 Git；
- 根目录没有 `package.json`，现有云函数也没有有效测试；
- 本机 Node.js 为 24.18.0，可以优先使用内置 `node:test`，避免一开始引入大型测试框架。

## 3. 所有 milestone 共用的完成标准

一个 milestone 只有同时满足以下条件才算完成：

- [ ] 按“一个行为测试 → 最小实现”的顺序完成 RED–GREEN 循环；
- [ ] 自动测试只通过公开接口验证行为，不测试私有函数或内部调用次数；
- [ ] 自己控制的模块使用真实实现，不互相 mock；
- [ ] 只在微信、CloudBase 数据库、时间、随机 ID 等系统边界使用替身；
- [ ] `npm test` 全部通过；
- [ ] 微信开发者工具编译无错误；
- [ ] 对本 milestone 的主流程完成 wechatide 自动化验证；
- [ ] 人类按验收步骤测试通过；
- [ ] 没有顺手实现下一个 milestone 的功能；
- [ ] 必要的设计变化已经更新到本文件或精简版项目文档；
- [ ] milestone 结束时代码处于可运行状态，并形成一个独立 Git 提交。

### TDD 执行方式

每个 milestone 下列出的“行为测试”是优先级顺序，不是一次性全部编写的测试清单。

```text
第 1 个行为：RED → GREEN
第 2 个行为：RED → GREEN
……
全部为 GREEN 后：REFACTOR → 再运行全部测试
```

## M0：开发地基

### 用户可见成果

QuickStart 页面被替换为简单的“家庭健康”应用壳。小程序能正常启动，并能通过统一接口确认云端可用。

### 范围

- 初始化本地 Git 仓库；
- 增加根目录测试入口，优先使用 `node:test`；
- 建立前端、云函数和共享业务代码的基础目录；
- 定义统一请求、成功响应和错误响应；
- 云函数只接受白名单 `action`；
- 配置独立的开发用 CloudBase 环境；
- 删除或隔离 QuickStart 的业务演示代码和 `sales` 示例，不继续沿用它作为产品架构；
- 建立最小应用壳、加载态和错误态。

### 首轮公开接口

```text
family-api.bootstrap()
```

M0 只要求它能识别云调用成功并返回统一结构，不在此阶段创建家庭。

### 行为测试顺序

1. 不支持的 `action` 返回稳定的 `UNSUPPORTED_ACTION`，而不是静默返回 `undefined`。
2. 成功结果使用 `{ ok, requestId, data }` 结构。
3. 失败结果只暴露稳定错误码和安全提示，不暴露调用栈。
4. 客户端提交的 `openid`、`userId` 或 `role` 不会成为可信身份。

### 自动验证

- 根目录执行 `npm test`；
- 微信开发者工具编译；
- 自动化打开首页，断言出现“家庭健康”标题；
- 调用开发环境中的 `bootstrap`，断言页面结束加载并显示进入入口；
- 检查 console 无未处理异常。

### 人类验收

1. 在微信开发者工具打开项目并编译；
2. 确认不再看到 QuickStart 功能列表；
3. 确认显示家庭健康应用壳；
4. 断开或填错开发环境时能看到清楚错误提示；
5. 恢复正确环境后能重新加载。

### 进入 M1 前的必要输入

- 用户确认一个专用于开发测试的 CloudBase 环境 ID；
- 确认可以删除 QuickStart 的示例页面、图片和示例云函数。

## M1：第一个家庭

### 用户可见成果

首次进入的用户可以创建普通家庭或个人空间，随后进入空的家庭首页。

### 范围

- 通过可信微信上下文创建或复用 `users`；
- 首次进入选择创建家庭或个人空间；
- 创建 `families`；
- 同一事务创建管理员 `family_memberships`；
- 查询本人有效家庭；
- 本地只保存当前家庭 ID；
- 当前家庭失效时不再信任本地缓存。

### 公开接口

```text
family-api.bootstrap
family-api.createFamily
family-api.createPersonalSpace
family-api.listMyFamilies
```

### 行为测试顺序

1. 同一微信身份重复 `bootstrap` 只得到一个用户。
2. 创建家庭会同时创建一份 `admin + active` 成员关系。
3. 创建家庭的任一步失败时，不留下无管理员家庭。
4. 个人空间使用同一家庭模型，且只有创建者一名成员。
5. `listMyFamilies` 不返回已经失效的成员关系。

### 自动验证

- 领域/应用服务测试使用内存仓储，通过公开 family service 验证；
- CloudBase 集成测试验证家庭和管理员成员关系原子创建；
- 自动化完成“首次进入 → 创建家庭 → 进入空首页”；
- 自动化完成“首次进入 → 创建个人空间”。

### 人类验收

1. 清理测试账号的初始化数据；
2. 打开小程序，创建“测试家庭 A”；
3. 确认自己显示为管理员；
4. 切换到另一个干净测试账号并创建个人空间；
5. 关闭并重开小程序，确认仍能进入上次有效空间。

### 不在本 milestone

- 家庭邀请；
- 健康档案；
- 健康记录。

## M2：家庭邀请、加入与多家庭切换

### 用户可见成果

管理员可以邀请另一名用户加入家庭；受邀用户确认档案代管选择后成为普通成员。一个用户可以加入多个家庭并切换。

### 范围

- 创建单次家庭邀请；
- 解析邀请时只返回家庭名等最小信息；
- 邀请过期、撤销和使用；
- 加入或重新加入家庭；
- 加入页的档案代管默认勾选，但必须由用户确认；
- 家庭列表和当前家庭切换；
- 普通成员不能创建或撤销邀请。

### 公开接口

```text
family-api.createInvite
family-api.resolveInvite
family-api.revokeInvite
family-api.joinFamily
family-api.listMyFamilies
```

### 行为测试顺序

1. 管理员可以创建有效的单次邀请。
2. 普通成员创建邀请会得到 `ADMIN_REQUIRED`。
3. 已建立微信身份后解析邀请时，只得到允许展示的最小家庭信息。
4. 使用邀请会创建或重新激活唯一成员关系，并把邀请改为 `used`。
5. 同一邀请重复使用不会产生第二份成员关系。
6. 加入请求必须明确提交代管选择；页面默认值为 `true`。
7. 用户只会看到自己拥有有效成员关系的家庭。

### 自动验证

- 邀请服务行为测试；
- 使用邀请的 CloudBase 事务集成测试；
- 自动化模拟“管理员生成邀请 → 受邀账号确认 → 家庭列表出现新家庭”；
- 自动化切换两个家庭并验证当前家庭标题。

### 人类验收

1. 账号 A 在“测试家庭 A”创建邀请；
2. 账号 B 打开邀请；
3. 确认加入页默认勾选档案代管；
4. 取消后再勾选，确认必须主动提交；
5. 加入后账号 B 显示为普通成员；
6. 再次打开同一邀请，确认不能重复加入；
7. 账号 B 在两个家庭间切换。

## M3：全局健康档案与家庭代管

### 用户可见成果

用户可以维护自己的全局健康档案；同家庭成员可以查看，只有获得家庭代管授权的人才能修改。

### 范围

- 每个用户一份 `health_profiles`；
- 本人查看和编辑；
- 同家庭有效成员查看；
- 通过指定家庭代管他人档案；
- 开启或关闭某个家庭的代管授权；
- 管理员不具有额外档案权限；
- 权限变化立即生效。

### 公开接口

```text
profile-api.getMyProfile
profile-api.getMemberProfile
profile-api.saveMyProfile
profile-api.saveManagedProfile
profile-api.setProfileManagementAllowed
```

### 行为测试顺序

1. 本人可以创建并更新自己的唯一档案。
2. 同家庭有效成员可以查看档案。
3. 没有代管授权时，普通成员和管理员都不能修改他人档案。
4. 获得代管授权的同家庭成员可以修改。
5. 双方任一成员关系失效后，代管立即失败。
6. 关闭授权后，旧页面再次保存会被云端拒绝。

### 自动验证

- 权限矩阵通过 `profile-api` 公开动作测试；
- 不直接查询数据库来判断测试是否成功，而是再次调用读取接口；
- 自动化完成本人编辑、他人查看和无权编辑提示。

### 人类验收

1. 账号 B 建立自己的健康档案；
2. 账号 A 查看 B 的档案；
3. B 关闭家庭代管，A 尝试修改并被拒绝；
4. B 开启家庭代管，A 修改成功；
5. 将 A 提升为管理员后再次关闭代管，确认管理员仍不能修改。

## M4：系统模板与第一条健康记录

### 用户可见成果

家庭成员可以用“体温”等系统模板，为本人或家人创建一条健康记录，并在家庭时间线中查看。

### 范围

- 系统模板配置；
- 第一版至少提供体温、血压、血糖和用药模板；
- 快速添加入口；
- 选择数据所属人；
- 动态字段表单的最小版本；
- 创建和读取健康记录；
- 保存模板名称和字段快照；
- 保存数据所属人、创建人、最后修改人；
- 选填备注；
- 基础记录时间线。

### 公开接口

```text
template-api.listTemplates
health-item-api.createRecord
health-item-api.getHealthItem
query-api.getRecordTimeline
```

### 行为测试顺序

1. 有效成员能看到家庭可用的系统模板。
2. 有效成员可以为同家庭成员创建体温记录。
3. 非成员不能读取或创建家庭记录。
4. 云端忽略前端伪造的创建人和最后修改人。
5. 记录保存自己的模板与字段快照。
6. 备注留空时不保存无意义空值。
7. 时间线只返回当前家庭未删除的数据。

### 自动验证

- 通过 `health-item-api` 创建并通过 `query-api` 读回；
- 动态字段校验使用真实模板配置；
- 自动化完成“快速添加 → 体温 → 保存 → 时间线出现记录”；
- 自动化为另一个家庭成员创建记录并检查所属人。

### 人类验收

1. 账号 A 为自己记录一次体温；
2. 账号 A 为账号 B 记录一次体温并填写备注；
3. 在健康记录页确认两条数据的所属人、时间和值正确；
4. 关闭并重开小程序，确认数据仍可读取。

## M5：自定义模板与记录生命周期

### 用户可见成果

家庭成员可以创建自定义健康项目；记录可以编辑、软删除和恢复，模板变化不会破坏旧记录。

### 范围

- 创建和编辑家庭自定义模板；
- 模板字段和选项的启用/停用；
- 事项中增加有限临时字段；
- 记录首次保存后不能切换模板或事项形式；
- `revision` 冲突保护；
- 记录编辑；
- 记录软删除和恢复；
- 已使用模板的历史保护。

### 公开接口

```text
template-api.createCustomTemplate
template-api.updateCustomTemplate
template-api.setTemplateStatus
health-item-api.updateHealthItem
health-item-api.softDeleteItem
health-item-api.restoreItem
```

### 行为测试顺序

1. 有效成员可以创建家庭自定义模板。
2. 使用模板创建的记录保存独立字段快照。
3. 模板改名或停用后，旧记录仍按原快照显示。
4. 已使用字段不能被破坏性删除。
5. 记录不能切换模板或变成提醒。
6. 旧 `revision` 的保存请求被拒绝，不静默覆盖。
7. 软删除后普通时间线不可见，恢复后重新可见。

### 自动验证

- 从模板创建记录、修改模板、再通过记录接口读取旧记录；
- 两个并发版本的更新测试；
- 自动化完成模板创建、记录使用、删除和恢复。

### 人类验收

1. 创建“晨间状态”自定义模板；
2. 使用它创建记录；
3. 修改模板名称并停用一个字段；
4. 打开旧记录，确认原数据仍完整；
5. 删除记录，确认时间线消失；
6. 从最小恢复入口恢复，确认重新出现。

## M6：一次性提醒、每日健康与打卡

### 用户可见成果

成员可以创建一次性提醒，在每日健康中提前或按时打卡；打卡产生一条且仅一条关联记录。

### 范围

- 创建和编辑一次性提醒；
- `pending`、`completed` 两个持久状态；
- 待开始、待打卡、未打卡等派生标签；
- 每日健康查询；
- 提前打卡；
- 打卡事务与幂等；
- 删除打卡记录时恢复原提醒；
- 恢复记录时处理关联冲突。

### 公开接口

```text
health-item-api.createReminder
health-item-api.updateHealthItem
health-item-api.checkInReminder
health-item-api.softDeleteItem
health-item-api.restoreItem
query-api.getDailyHealth
```

### 行为测试顺序

1. 一次性提醒创建后出现在对应日期。
2. 计划时间前可以打卡。
3. 打卡在同一事务创建记录并完成提醒。
4. 相同 `requestId` 重试只返回同一结果。
5. 两个成员同时打卡只产生一条关联记录。
6. 删除关联记录会把提醒恢复为 `pending`。
7. 原提醒空闲时可恢复记录并重新完成提醒。
8. 原提醒已有新记录时阻止旧记录恢复。
9. 原提醒已不存在时，记录可作为独立记录恢复。

### 自动验证

- 使用可控制时间边界测试派生标签；
- CloudBase 集成测试验证打卡事务和并发；
- 自动化完成提醒创建、提前打卡和每日健康刷新；
- 自动化完成删除关联记录与提醒恢复。

### 人类验收

1. 创建今天稍晚的体温提醒；
2. 在计划时间前打卡；
3. 确认提醒显示完成且时间线只出现一条记录；
4. 重复点击或重新提交，确认不会新增第二条；
5. 删除打卡记录，确认提醒恢复未完成；
6. 再次打卡并检查结果。

## M7：周期规则与未来提醒

### 用户可见成果

成员可以创建、暂停和恢复周期规则。后台会生成未来提醒，重复运行不会产生重复项。

### 范围

- 创建、编辑、暂停和恢复周期规则；
- 日期范围和每日多个时间；
- 后台生成未来 30 天一次性提醒；
- `dedupKey` 防重复；
- 未开始、进行中、已结束标签由日期推导；
- 规则改变后只协调未来未打卡提醒；
- 过去提醒和记录不被改写。

### 公开接口

```text
health-item-api.createRecurringRule
health-item-api.updateHealthItem
health-item-api.pauseRule
health-item-api.resumeRule
reminder-materializer.materialize
```

### 行为测试顺序

1. 有效规则会生成日期范围内的未来提醒。
2. 同一规则、日期和时间重复执行只产生一条提醒。
3. 暂停规则后不再生成新提醒。
4. 恢复规则只补齐未来缺失提醒。
5. 修改时间只协调未来未打卡提醒。
6. 过去提醒和记录保持不变。
7. 删除后恢复会保留删除前的暂停状态。

### 自动验证

- 注入固定时钟，测试跨天、开始日和结束日；
- 连续运行两次 materializer，读回结果数量一致；
- 微信开发者工具中提供仅开发环境可见的“立即运行调度”方式；
- 自动化创建短周期规则并验证每日健康列表。

### 人类验收

1. 创建一个未来三天、每天两个时间的测试规则；
2. 手动触发开发环境调度；
3. 确认出现正确数量的提醒；
4. 再触发一次，确认数量不增加；
5. 暂停并触发，确认不增加；
6. 恢复后只补齐缺失的未来提醒。

## M8：家庭角色、退出和成员清理

### 用户可见成果

管理员可以管理普通成员和管理员身份；成员可以安全退出，任何操作都不会让家庭变成零管理员。

### 范围

- 提升普通成员为管理员；
- 管理员在仍有其他管理员时降级自己；
- 禁止降级或移除另一名管理员；
- 移除普通成员；
- 普通成员主动退出；
- 唯一管理员转让后退出；
- 无接任者时阻止唯一管理员退出；
- 成员离开后，历史保留；
- 以离开者为数据所属人的规则暂停，未来自动提醒清理；
- 不因为离开者只是创建人就暂停规则。

### 公开接口

```text
family-api.promoteMemberToAdmin
family-api.demoteSelfFromAdmin
family-api.removeMember
family-api.leaveFamily
family-api.transferAdminAndLeave
family-api.dissolveFamily
```

### 行为测试顺序

1. 普通成员不能执行管理员动作。
2. 管理员可以提升有效普通成员。
3. 管理员不能降级或移除另一名管理员。
4. 有其他管理员时可以降级自己。
5. 唯一管理员不能降级自己。
6. 唯一管理员转让并退出是一个受保护操作。
7. 两名管理员同时自我降级后仍至少保留一名管理员。
8. 普通成员退出后立即失去访问权限，历史保留。
9. 成员离开后的提醒清理只影响以其为数据所属人的未来事项。

### 自动验证

- 使用公开 family service 完成权限矩阵测试；
- CloudBase 事务测试两个并发角色变化；
- 自动化覆盖普通成员无权入口和唯一管理员阻止提示；
- 两账号退出后验证旧家庭不再出现在列表。

### 人类验收

1. 使用至少两个账号，最好三个；
2. A 提升 B 为管理员；
3. A 尝试移除 B，确认被拒绝；
4. A 自我降级成功；
5. 此时 B 成为唯一管理员，尝试自我降级并被拒绝；
6. B 选择 A 为接任者后退出；
7. 确认家庭始终有管理员，过去健康数据仍保留。
8. 新建一个无业务数据的临时家庭，二次确认解散并验证它不再出现。

## M9：微信通知、权限回归与发布候选版

### 用户可见成果

核心闭环可在真机使用；数据所属人可以选择微信通知，拒绝或发送失败不影响小程序内提醒。

### 范围

- 数据所属人本人发起微信订阅授权；
- 家人创建提醒时不能代替数据所属人授权；
- 微信通知适配器；
- 通知失败不改变业务提醒状态；
- 必要的技术重试和防重复；
- 全部权限矩阵回归；
- 加载、空状态、离线和错误提示；
- 按真实查询补充数据库索引；
- 清理开发专用入口和测试数据；
- 生成手机预览或体验版。

### 公开接口

业务接口保持不变。微信能力隐藏在通知适配器后，不把微信模板细节扩散到提醒模块和页面。

### 行为测试顺序

1. 只有数据所属人的本人交互流程会请求自己的微信订阅授权，不保存可替代微信平台结果的永久授权状态。
2. 家人为他人创建提醒不会产生“已替对方授权”的状态。
3. 未授权或拒绝授权时，小程序内部提醒仍可查看和打卡。
4. 微信发送失败不会把业务提醒标记为失败。
5. 技术重试不会重复完成提醒或产生重复记录。
6. 非成员、失效成员和伪造角色无法访问家庭数据。
7. 所有核心写操作重复提交都保持幂等。

### 自动验证

- 微信接口只在系统边界使用替身；
- 完整 Node 测试套件；
- CloudBase 开发环境权限回归；
- wechatide 自动化串联首次进入、记录、提醒、打卡、档案和家庭管理；
- 编译、console、network 和关键页面截图检查；
- 生成预览版供真机验收。

### 人类验收

1. 使用两台真机或两个微信账号；
2. 完成创建家庭、邀请加入和代管确认；
3. 为本人和家人分别创建记录与提醒；
4. 数据所属人授权一次微信通知；
5. 另一人尝试替其授权，确认不能完成；
6. 拒绝授权后确认小程序内提醒仍正常；
7. 完成打卡、记录删除恢复和周期规则测试；
8. 完成管理员转让与退出测试；
9. 检查主要空状态、失败提示和重新进入后的数据。

### 发布候选版通过条件

- [ ] 精简版项目文档中的第一轮验收清单全部通过；
- [ ] 没有 P0/P1 权限、数据丢失或重复数据问题；
- [ ] 真机核心流程可完成；
- [ ] CloudBase 开发环境与未来生产环境配置分离；
- [ ] 未实现的高级功能没有显示为可用入口。

## 5. 明确推迟到核心版本之后

以下内容不应悄悄进入 M0–M9：

- 可配置首页卡片；
- 进阶分析和分析导出；
- 关心分享；
- 跨家庭复制和个人空间数据导入；
- 家庭数据导出；
- 完整容量管理和回收站界面；
- 独立 Web 管理后台；
- 微服务、消息队列集群或数据仓库。

## 6. 开发者工具场景分工

后续执行 milestone 时按 wechatide skill 的 scene 边界使用：

| 目的 | Scene |
| --- | --- |
| 确认登录、窗口、当前页面 | `initializer` |
| 编译、刷新模拟器、构建 npm | `compiler` |
| 点击、输入、导航和页面断言 | `automator` |
| console、network、截图和故障取证 | `debugger` |
| 云环境、集合和云函数部署 | `cloudbase-operator` |
| 手机预览和体验版 | `previewer` |

失败时先停留在当前 scene 取证，不用多个工具无差别重试。

1. 是否同意 M0–M9 的边界和顺序；
2. 是否允许 M0 删除 QuickStart 示例页面、示例图片、`quickstartFunctions` 和 `sales` 示例；
3. 选择或创建一个专用于开发测试的 CloudBase 环境，并提供环境 ID，或者授权在 M0 中通过开发者工具完成该选择。
